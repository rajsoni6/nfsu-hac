1. ROLES
--------------------------------------------------------------------------------
Role          Description                                                                                       
----------    ------------------------------------------------------------------
admin         Full system access. Manages users, policy, exports, audit logs.
coordinator   Scoped to own assigned course. Manages students and views offers.
student       Read-only access to own profile, own offers, company list.
recruiter     Access to own company's offers and company stats only.

3. BACKEND ENFORCEMENT
--------------------------------------------------------------------------------
File: backend/src/middleware/authorize.js

The authorize() middleware is applied at the route level:

  router.get('/',              authorize('admin', 'coordinator'), ctrl.getAll);
  router.post('/',             authorize('admin'),                ctrl.create);
  router.get('/me',            authorize('student'),              ctrl.getMe);
  router.get('/:id',           authorize('admin','coordinator','student'), ctrl.getOne);
  router.put('/:id',           authorize('admin', 'coordinator'), ctrl.update);
  router.patch('/:id/archive', authorize('admin'),                ctrl.archive);
  router.get('/export',        authorize('admin'),                ctrl.exportData);

Additional scoping inside controllers:
  - Coordinator: filter.course = req.user.courseAssigned
  - Student: verified req.user.studentRef === student._id before returning data
  - Recruiter: offer queries filtered by req.user.companyAssigned

--------------------------------------------------------------------------------
4. FRONTEND ENFORCEMENT
--------------------------------------------------------------------------------
File: frontend/js/app.js — requireAuth(allowedRoles)
File: frontend/pages/*.html — requireAuth(['admin','coordinator']) at page load

  requireAuth(['admin'])              → admin-only pages
  requireAuth(['admin','coordinator'])→ management pages
  requireAuth(['student'])            → student profile page
  requireAuth(['recruiter'])          → recruiter portal

Role-based UI hiding:
  - data-roles="admin" attribute hides elements from non-admin users
  - Export button hidden for all roles except admin
  - Edit/Archive buttons hidden for student and recruiter roles
  - Sidebar navigation links filtered by role

--------------------------------------------------------------------------------
5. IDOR PREVENTION
--------------------------------------------------------------------------------
IDOR (Insecure Direct Object Reference) is prevented by:

  Student access:
    Controller checks req.user.studentRef === student._id
    Returns 403 if student attempts to access another student's record

  Coordinator access:
    Controller checks student.course === req.user.courseAssigned
    Returns 403 if coordinator attempts cross-course access

  Recruiter access:
    Offer queries filtered by company: req.user.companyAssigned
    Returns 403 if recruiter attempts to access other company's data

Security test cases covering IDOR:
  - Student modifies own placement status via direct API call → 403
  - Student accesses another student's record by ID manipulation → 403
  - Recruiter creates or edits an offer → 403
  - Coordinator accesses students outside own course → 403
